# I2 — Task/DSQ ownership and valid state transitions (v7.1)

Machine-readable form: [`I2.yaml`](I2.yaml). Kernel: Linux **v7.1**
(`8cd9520d35a6c38db6567e97dd93b1f11f185dc6`), the course kernel. All `file:line` references are for that commit
(`ext.c` = `kernel/sched/ext.c`).

**Invariant.** At any time a sched_ext task has exactly one owner, and the fields that record ownership change only
along legal transitions:

* **DSQ membership.** A task is linked into at most one DSQ. `p->scx.dsq`, the DSQ list or priq node and `dsq->nr`
  change together under the DSQ's protecting lock: `dsq->lock` for a non-local DSQ, the owning rq lock for a local one.
* **`p->scx.ops_state`.** This is the hand-off token between the SCX core and the BPF scheduler: NONE, QUEUEING,
  QUEUED, DISPATCHING, plus a QSEQ.
* **`p->scx.holding_cpu`.** It names the CPU that is moving the task between rqs.
* **Lifecycle state** (`p->scx.flags & SCX_TASK_STATE_MASK`). It changes only through `scx_set_task_state()`.

I1 says *which lock* protects a write. I2 says *who owns the task* while it is written, and which state edges are
legal. Each rule has `role: protection`, with obligations that bind each write site to its lock, predicate or
ownership token, plus `requires.transitions` for the two state machines.

| Rule | Status | Enforcement |
|---|---|---|
| `I2.dsq_membership.single_dsq` | source_verified | lock, WARN (not preventive), lockdep |
| `I2.ops_state.transitions` | source_verified | atomic/cmpxchg, rq lock, QSEQ guard, WARN, BUG |
| `I2.holding_cpu.handoff` | source_verified | dsq/rq lock, release store, re-check guard, WARN |
| `I2.dsq_move.ownership_recheck` | source_verified | locks, `nldsq_cursor_lost_task` guard, `scx_error`, WARN |
| `I2.task_state.transitions` | source_verified | **WARN only** (the invalid write still happens) |
| `I2.task_state.serialization` | **draft** | none (hypothesis) |

## 1. `ops_state` transitions

| From → To | Primitive | Where (ext.c) | Who owns `p` / held |
|---|---|---|---|
| NONE → QUEUEING\|qseq | `atomic_long_set` | `do_enqueue_task` 1942 (qseq = `rq->scx.ops_qseq++` 1939) | core, `task_rq(p)` locked; WARN unless NONE (1941) |
| QUEUEING → QUEUED\|qseq | `set_release` | `do_enqueue_task` 1964 | hands `p` to BPF, rq locked |
| QUEUEING → NONE | `set_release` | `direct_dispatch` 1849; `dispatch_enqueue` 1643 (`SCX_ENQ_CLEAR_OPSS`, from 1868) | direct dispatch, rq locked |
| QUEUED → DISPATCHING | `try_cmpxchg` | `finish_dispatch` 2724 | dispatching CPU. QSEQ must match the value captured at insert (2708), else drop |
| QUEUED → NONE | `try_cmpxchg` | `ops_dequeue` 2109 | dequeue, `task_rq(p)` locked |
| DISPATCHING → NONE | `set_release` | `dispatch_enqueue` 1643 (after linking); `dispatch_to_local_dsq` 2622 (after setting `holding_cpu`) | dispatcher → DSQ or `holding_cpu` |

Observers wait with `wait_ops_state()` (`atomic_long_read_acquire`, 1076-1081), which pairs with the release exits
(ext_internal.h:1303-1306). `ops_dequeue` can never observe QUEUEING under the rq lock: it calls `BUG()` (2093), and
after waiting on DISPATCHING it calls `BUG_ON(!= NONE)` (2128). One edge is outside the table: in `direct_dispatch`
1851-1855, if `p` is QUEUED or DISPATCHING, the kernel WARNs and forces NONE (error recovery).

## 2. Lifecycle (`scx_set_task_state`, ext.c:719-757)

| To | Accepted from | Main sites |
|---|---|---|
| NONE | any but DEAD | `scx_disable_and_exit_task` 3735, `scx_fork` error 3777, root enable error 7004 |
| INIT_BEGIN | NONE | `scx_fork` 3774, `scx_root_enable_workfn` 6995 (under the iter rq lock), `scx_sub_disable` 5851 |
| INIT | INIT_BEGIN | 3780, 5852, 7021 |
| READY | INIT, ENABLED | `scx_post_fork` 3790, `scx_disable_task` 3660, 5854, 7023 |
| ENABLED | READY | `scx_enable_task` 3646 |
| DEAD | NONE, INIT_BEGIN | `sched_ext_dead` 3892 (`task_rq_lock`) |

An invalid edge only triggers `WARN_ONCE` (752-753), and the new state is written anyway (755-756). Only an undefined
target value returns without writing (746-749). The protection comes from callers: they re-check for DEAD after
retaking the rq lock (5829, 7003, 7013).

## 3. Ownership across DSQs and rqs

* **`dispatch_enqueue` / `move_local_task_to_local_dsq`.** Both link `p` and set `p->scx.dsq` in the same critical
  section as `dsq_inc_nr` (1613-1614, 2266-2267). The "not on a DSQ" precondition is `WARN_ON_ONCE` only (1524-1526).
* **`unlink_dsq_and_lock_src_rq` (2406-2424).** Under the asserted `dsq->lock` it does three things: WARNs unless
  `holding_cpu < 0`, unlinks `p` and sets `holding_cpu = cpu`. It then switches from the DSQ lock to `src_rq`, and
  continues only if `holding_cpu == cpu && src_rq == task_rq(p)`. `p->scx.dsq` stays set during this window, while
  `p` is on no list.
* **`dispatch_to_local_dsq` (2581-2660).** It owns `p` through DISPATCHING. It sets `holding_cpu` (2619), releases
  NONE (2622), switches to `src_rq`, then re-checks (2632). If the check fails, dequeue has won and `p` is dropped.
* **`dispatch_dequeue` (1668-1719).** It is the counterpart: under the rq lock (and `dsq->lock`), it clears
  `holding_cpu` to -1 instead of unlinking when a mover has already taken `p`.
* **`move_remote_task_to_local_dsq` (2281-2307).** It migrates with `deactivate_task` / `activate_task` under
  `src_rq`, then `dst_rq`. WARNs: the destination CPU must be allowed (2302) and `extra_enq_flags` must be clear (2303).
* **`scx_dsq_move` (8344-8438).** After taking `task_rq(p)` and `src_dsq->lock` it re-checks ownership with
  `nldsq_cursor_lost_task` (673-694): same DSQ, no newer `dsq_seq`, `holding_cpu < 0`, and the same rq (WARN). A task
  of another scheduler gets `scx_error` (8374-8377).

## 4. Worked example: `scx_bpf_dsq_move_to_local___v2`

This is the same root as I1. Entry: `balance_one` (rq lock asserted 2890) → `scx_dispatch_sched` → `ops.dispatch`.

1. **Flush.** 8530 `flush_dispatch_buf(sch, dspc->rq)` → 2757 `finish_dispatch(...)`. `p` is QUEUED. The QSEQ check
   (2708) passes, and `try_cmpxchg` QUEUED → DISPATCHING (2724) makes this CPU the owner. It holds only its own rq.
2. **Remote local DSQ.** 2744 `dispatch_to_local_dsq`: `holding_cpu = this CPU` (2619), then `set_release` →
   NONE (2622). It drops `rq` and locks `src_rq` (2626-2628), and re-checks `holding_cpu` (2632). On success it calls
   `move_remote_task_to_local_dsq`. If a concurrent `ops_dequeue` saw NONE, its `dispatch_dequeue` reset
   `holding_cpu` (1689-1690) and the move is skipped.
3. **Consume.** 8538 `consume_dispatch_q` → 2549 `consume_remote_task` → 2432 `unlink_dsq_and_lock_src_rq`. Ownership
   moves from `dsq->lock` to `holding_cpu` (2416) and then to `src_rq` (2419-2423).

In `I2.yaml` these are the `paths` of `I2.ops_state.transitions/claim_qseq`, `/exit_release` and
`I2.holding_cpu.handoff/claim_from_dsq`.

## 5. Gaps worth testing

1. **WARN-only preconditions.** Three checks warn and then do the bad thing anyway: double enqueue (1524),
   `ops_state != NONE` on enqueue (1941) and invalid lifecycle edges (752). Fault injection should show list corruption
   or a bad state after the WARN.
2. **`direct_dispatch` forcing NONE (1851-1855).** It resets an unexpected QUEUED or DISPATCHING. If a remote
   `finish_dispatch` holds DISPATCHING at that point, two owners may exist.
3. **`move_task_between_dsqs` remote branch (2493-2496).** It unlocks `src_dsq` before `deactivate_task` unlinks `p`.
   A concurrent `consume_dispatch_q` can claim `p` via `holding_cpu` and must lose to `dispatch_dequeue`. This needs a
   stress test with `scx_bpf_dsq_move` against `scx_bpf_dsq_move_to_local` on the same DSQ.
4. **Lifecycle writes without the rq lock.** `scx_fork` and `scx_post_fork` (3774-3790) rely on `p` not yet being on
   `scx_tasks`. `scx_set_task_state` asserts no lock (draft `I2.task_state.serialization`).
5. **Stale `p->scx.dsq`.** While `holding_cpu` is set, `p->scx.dsq` is non-NULL but `p` is on no list. A reader that
   trusts `p->scx.dsq` alone, such as the dump at 6292 or a BPF iterator, sees an inconsistent view.
6. **QSEQ wrap.** QSEQ has 30 bits on 32-bit and 62 bits on 64-bit (ext_internal.h:1355-1364). A stale dispatch-buffer
   entry could match a wrapped QSEQ; this is only practical on 32-bit.
